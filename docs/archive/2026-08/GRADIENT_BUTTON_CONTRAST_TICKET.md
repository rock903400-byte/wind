# 工單 WIND-UI-07｜漸層按鈕深色模式對比度，與掃描器的漸層盲點

> 小工單：2 個按鈕 + 1 個掃描腳本。但第 3 節有一個**會反向弄壞淺色模式**的陷阱，
> 動手前必讀。完成後由發單方（Claude）依文末〈驗收清單〉檢驗。

---

## 1. 背景

WIND-UI-01 ~ 06 之後，全站「7 頁 × 深淺兩主題對比度未達 AA = 0」——
**但那個結論從頭到尾不包含任何漸層按鈕。**

驗收用的掃描腳本有一條 `hasImg` 過濾：元素或其祖先只要有 `background-image`
就整個跳過（原意是避免半透明疊層算錯）。漸層正是 `background-image`，
所以每一顆漸層按鈕都被靜默略過了。

實測結果：

| 按鈕 | 淺色 | 深色（預設主題） |
|---|---|---|
| `index` `.btn-primary`（`#contact` 的「LINE 免費聊聊」主 CTA）| #047857→#0e7490 白字 **5.36** ✅ | #10b981→#0ea5e9 白字 **2.54** ❌ |
| `404` `.btn-primary` | #0369a1→#4338ca 白字 **5.93** ✅ | #0284c7→#6366f1 白字 **4.10** ❌ |

WIND-UI-02 的 T-5 只修了淺色，深色從此沒人再看。
**這是發單方驗收方法的盲點，不是任何一次實作的問題。**

首頁那顆是主要 CTA，2.54:1 —— 目前唯一實質的使用者可見缺陷。

## 2. 任務

### T-1｜`index` 的 `.btn-primary`：保留鮮豔漸層，深色模式改用深字

**檔案**：`assets/style.css`

**已定決策**：深色模式**保留** `#10b981 → #0ea5e9` 的鮮豔漸層，改把文字換成深色。
理由是那是首頁主 CTA，深色底上一顆亮綠轉青的按鈕比壓暗的更抓眼；
同樣手法在 WIND-UI-04 用於 `print-card` 的 LINE 綠按鈕。**不要改成壓深漸層。**

現況（`assets/style.css:368`，這是**基底規則，即深色模式**）：

```css
.btn-primary{...;background:var(--grad);color:#fff;...}
.btn-primary:hover{color:#fff;...}          /* :369 */
```

要求：
1. 基底的 `color` 由 `#fff` 改為 **`#04130d`**（on #10b981 = 7.50、on #0ea5e9 = 6.86，最差 6.86）。
   `:hover` 那條的 `color:#fff` 也要一起改，否則滑過去就變回白字。
2. **同時**在 `[data-theme="light"]` 區段新增 `.btn-primary` 與 `.btn-primary:hover`
   的 `color: #ffffff` 覆寫。**這一步不可省略** —— 見第 3 節。

### T-2｜`404` 的 `.btn-primary`：白字，壓深漸層

**檔案**：`404.html`

這顆**不能**走 T-1 的深字方案：藍紫漸層配深字最好只有 **4.26**，仍不合格。
所以維持白字、把深色模式的漸層壓深。

現況（`404.html:115-117` 基底 = 深色）：

```css
.btn-primary { background: linear-gradient(135deg, #0284c7, #6366f1); color: #ffffff; }
```

要求：基底漸層改為 **`#075985 → #3730a3`**（白字 7.56 / 9.93，最差 7.56）。
選這組而非直接沿用淺色的 `#0369a1 → #4338ca`（5.93），是為了讓深淺兩個主題仍有
可辨識的深淺差異 —— 淺色模式的覆寫（`:174`）維持不動。

**注意**：`:178` 的 `[data-theme="light"] .btn-primary:hover` 目前用的正是
`#075985 → #3730a3`。基底改成同一組後，淺色 hover 與深色靜止會撞色。
請把淺色 hover 再壓深一階（例如 `#0c4a6e → #312e81`，白字 9.46 / 11.42），
維持「hover 比靜止更深」的既有方向。

### T-3｜修掉掃描腳本的漸層盲點

**檔案**：`docs/CONTENT_MAINTENANCE.md`

目前 `CONTENT_MAINTENANCE.md` 的「無障礙基準線」段落把
`docs/archive/2026-08/A11Y_LANDMARK_DARKMODE_TICKET.md` 第 4-1 節的腳本
指為對比度檢查的標準工具，但那份腳本有上述盲點。

要求：**在 `CONTENT_MAINTENANCE.md` 內放一份修正版腳本**（不要去改已歸檔的工單），
並把基準線段落的指向改為這份。修正重點：

- 不再對漸層底元素直接 `return`。改為抓出 `background-image` 裡所有
  `rgb()/rgba()` 色標，**逐一計算並取最差值**。
- 仍要保留對「祖先有裝飾性漸層」的處理 —— 那種情況（例如 body 的光暈）
  取最差值會過度嚴格。建議只對**元素自身**有 `background-image` 時做色標計算，
  祖先仍沿用現行的略過邏輯，並在註解寫明這個界線。
- 腳本輸出要能區分「一般元素」與「漸層元素」，方便判讀。

## 3. 陷阱：深色是基底，改基底會連帶弄壞淺色

`assets/style.css:368` 的 `.btn-primary` 是**基底規則**，深色模式直接吃它，
淺色模式目前**沒有** `color` 覆寫（`grep '\[data-theme="light"\] .btn-primary'` 為空），
所以淺色也是沿用基底的 `color:#fff`。

也就是說：**只把基底改成 `#04130d`，淺色模式會跟著變深字**，而淺色的漸層是
`#047857 → #0e7490`，配深字只有 **3.47 / 3.55 —— 直接壞掉**。

所以 T-1 的第 2 步（在淺色區段補回 `color:#ffffff`）是必要的，不是可選的。
**改完務必兩個主題都量。**

## 4. 禁止事項

- 不得改動 `--accent2`（`assets/style.css:14`）。實心色只用在 `--grad` 這一處，
  但 `--accent2-rgb` 有 5 處裝飾用途（透明度 0.1~0.5），改了會牽動 hero 光暈、
  跑馬燈遮罩、導覽 active 態等。**這次不碰變數，只改按鈕自己的宣告。**
- 不得改動 `404.html` 的 `[data-theme="light"] .btn-primary` 靜止態（`:174`）。
- 不得改動 CSS 或 HTML 的其他 `[data-theme]` 規則，或任何 JS。
- 不得放寬 `scripts/verify-site.py` 任何斷言。
- 不得去改 `docs/archive/` 下任何已歸檔工單。

**分支**：從 `main` 切 `fix/gradient-button-contrast`，T-1+T-2 一個 commit、T-3 一個 commit。
**不要直接推 main、不要自行 merge。**
